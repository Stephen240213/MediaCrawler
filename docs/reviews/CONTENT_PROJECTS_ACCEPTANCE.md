# 第一轮：内容项目贯通与生产基础

> 本文命令及行内文件路径均以项目根目录为基准。

用户授权继续本地实施。本轮实现项目入口、关系汇集、编辑恢复、素材索引、完整备份及固定回归；保持现有采集、分析、改写、制作和发布回填方式。照片背景、语义版式、新视频渲染和付费工具接入属于后续阶段。

## 内容项目

- 从左侧「内容项目」创建名称、账号画像、题材、创作目标与工作笔记，可归档而不删除原内容。
- 可关联已有小红书资料、分析任务、普通草稿和本机素材；解除关联不删除资料。记录不可用时保留关联并显示缺失。
- 关联分析后，自动汇集它的已有及后续成稿、采用稿、制作版本和人工回填发布记录。项目阶段根据已有记录显示，制作版本存在不等于已发布。
- 从项目打开分析与制作，或在该项目下新建分析；分析页也可选择项目并关联历史任务。不会因关联重新采集、调用模型或重新生成报告。
- 发布回填增加「实际采用的制作版本」。必须属于所选成稿与任务；已有观测后不允许悄悄更改该关联。历史记录可以留空，不推断使用过哪一版封面。
- 项目创作说明本轮用于整理，不会自动发送模型；模型仍仅接收用户确认的分析输入。关联源不意味着图片/正文具有再发布授权。

验收：创建项目→关联已有分析→打开并保存成稿/制作→返回项目刷新→核对成品；关联工作台草稿并打开；回填发布时选对应制作；检查归档及解除关联保持原文件。

## 编辑恢复与冲突

- 项目笔记、改写编辑、制作草案和普通草稿可保留未完成编辑。浏览器本机保存最后修改，约600毫秒后同步到后端恢复稿。
- 恢复稿按登录身份和编辑范围隔离，与正式项目/成稿/制作版本分开。恢复不会调用模型或标记发布。
- 再次进入编辑器发现恢复稿时，明确选择「恢复未完成编辑」或「使用当前内容」。服务异常时显示提示，保留浏览器副本；浏览器存储不等于备份。
- 后端恢复稿使用修订号检测多页面写入冲突；正式项目也有独立版本检查。发生冲突保留编辑，不自动覆盖。核对最新项目内容后，可明确选择使用当前编辑继续保存。
- 未登录同一身份、清理浏览器存储或切换浏览器时，本机未同步的最后修改不保证可用；已同步的恢复稿仍可由同身份读取。
- 完成的新建项目会清理「新项目」恢复槽，避免下一次新建时误恢复为已创建项目。

验收：编辑未保存正文/笔记→切换页面或刷新→恢复→保存正式版本；两个页面并行编辑检查冲突，确认旧报告和正式版本保持不变。

## 素材索引

- 素材元数据、SHA-256和文件状态进入工作台数据库索引，首次读取建立索引；常规列表不再反复遍历目录。
- 图片导入更新索引；采集结束使索引失效，下一次读取重新整理。外部手动增删文件后，点击「刷新素材」重新索引。
- 素材管理支持按名称/路径搜索、图片/视频筛选和每页48项分页。兼容原素材路径、草稿配图及旧接口调用。
- 图片生成最长边480像素的缩略图供列表预览，下载和大图仍使用原文件。视频本轮只索引，不提取视频封面。
- 归档只影响素材库显示，保留文件与草稿引用。符号链接和目录越界不进入索引/缩略图读取。

验收：多页与搜索、归档恢复、外部新增后刷新、图片尺寸与下载原图；不把首次建立索引耗时当作常规列表耗时。

## 完整备份与恢复

保留原有单库在线备份；新增完整工作区备份需要先停止工作台和采集，以便一致保存多库与引用文件。不会替用户停止任务或覆盖已有恢复目录。

```bash
# 在项目目录执行；使用现有私有配置，勿复制配置内容到Git。
.venv/bin/python -E -m api.desktop stop
.venv/bin/python -E -m api.backup --full --env-file "$HOME/.config/mediacrawler/remote.env" --destination .runtime/backups
.venv/bin/python -E -m api.desktop start

# 将实际生成的 workspace-日期目录替换到下方路径。
.venv/bin/python -E -m api.backup --verify /absolute/backup/workspace-TIMESTAMP
.venv/bin/python -E -m api.backup --restore /absolute/backup/workspace-TIMESTAMP --destination /absolute/new-recovery-directory
```

- 备份采集库、工作台库、分析库和检查点；复制data下支持的媒体，以及转写、上传、制作文件和缩略图。备份目录含摘要清单。
- 不复制私有环境配置、Cookies、浏览器资料、模型、锁文件或旧备份目录。备份自身仍包含私人内容，应仅存放在可信本机位置，不上传Git。
- 验证SQLite完整性、文件摘要、大小和路径，并核对草稿配图、制作产物和完整上传的数据库引用。缺失或损坏时失败，不交付看似完整的备份。
- 恢复只写入尚不存在的新目录，核验后复制并复验；不覆盖线上数据。恢复布局为 `collection.sqlite3`、`runtime/`、`data/`，私有配置需单独提供并指向正确路径。
- 采集源文件/用户手动目录已经缺失时，需要先找回引用或处理记录；备份不能恢复从未保存的素材。

## 回归入口与环境

`scripts/cloud-check.sh` 已纳入Remix、项目、素材索引、备份恢复、权限及完整浏览器fixture；前端构建后再执行浏览器测试。Linux cloud-setup补充FFmpeg与中文字体依赖，本轮未实际运行云端部署或新安装依赖。

本轮本机使用已有Python 3.11、Node 22、FFmpeg与Chrome测试，模型和平台请求全部为fixture。运行数据、恢复稿、缩略图及备份均不提交Git。

本地验收结果：固定入口工作台64项、内容生产及权限150项、完整浏览器3项通过，合计217项；TypeScript及生产构建通过。浏览器检查了新建/关联项目、未完成编辑恢复、历史成稿自动汇集和移动端布局。另以隔离数据验证四库备份、空目录恢复、损坏摘要/路径拒绝及引用文件缺失时失败。

上线前已确认本机采集与分析空闲，停止工作台后创建并验证完整备份，再启动更新服务。上线检查确认新项目接口、新表、素材索引、历史报告和前端资源正常；未向真实生产数据填入fixture项目或发布效果。
