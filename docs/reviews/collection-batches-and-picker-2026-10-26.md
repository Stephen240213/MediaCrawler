# 采集参数、批次资料与直接选材调整

本轮针对用户的七处页面反馈实施。沿用此前本地开发授权；未运行真实平台采集、登录、发布或真实付费模型。运行数据和历史任务均不纳入代码提交。

## 参数与结果对应

- 网页搜索的滚动次数和内容条数是不同限制。配置接口返回项目默认条数，采集表单显示当前实际条数、起始批次、滚动上限和超时，并把实际条数显式传给后端。
- 任务保存不含 Cookie 的生效参数；进度同时显示内容上限和滚动预算，避免把首批发现数量误认为滚动设置被重置。
- 网页搜索允许起始批次大于1。后端沿已校验的网页筛选结果逐批加载并跳过前批；跳过也消耗滚动/时间额度，不将不稳定的无限滚动冒充固定网页分页。
- 普通接口搜索直接从指定页开始，不再把小于20的内容限制改成20，也不再将30等条数向下取整为一整页。最后一页有内容时仍处理，按设置的条数截止；失败尝试也受同等请求预算约束，不会为了凑足结果无限翻页。

## 重复内容与资源复用

- 网页搜索默认复用本机 SQLite 原始笔记，按平台内容ID去重。已有内容不再请求详情或评论；勾选「刷新已有内容与评论」后才重新获取。
- 普通接口搜索也复用本机已有 SQLite 笔记。指定内容/作者采集仍按明确指定目标执行更新。
- 媒体复用沿用现有下载器对同名、非空成品文件的检查；缺失媒体可用已经保存的地址补下载。地址失效时由用户选择刷新，不暗中增加详情请求。
- 复用不会丢掉新的来源关键词关联。默认复用是已有快照，不承诺互动或评论始终是最新值；需要新评论或指标时开启刷新。
- 此轮复用路径针对 SQLite 保存模式。独立文件/其他数据库没有统一可验证的本机正文缓存时，不把同名文件当成相同笔记；仅有文件的历史可先导入本机资料库。

## 任务、资料库与内容研究

- 新采集在成功保存后发送不含凭证的内容成员事件；复用也记录成员。按任务/平台/内容ID/关键词保存精确关系，多关键词命中同一内容时只计一篇。
- 新任务显示新增、复用、刷新和本次总数，批次短ID与生效参数用于区分相同检索词下的不同任务。
- 任务记录提供「查看资料」「内容分析」。前者打开按本次成员过滤的本机内容资料库；后者建立该批次研究范围，先预览增量与费用边界，不自动付费。
- 历史任务缺少成员表时，只从明确的笔记保存日志提取可追溯ID。原日志发生在保存尝试之前，所以明确标为历史可追溯范围，不伪称完整成功快照；没有日志时也不按相同关键词猜测归属。资料是否可分析由当前 SQLite 可用性另行显示。
- 批次页面展示的是本次成员及其当前资料版本，不是当时正文快照；研究执行时才冻结正文、评论与版本。
- 内容研究新增三种纳入方式：直接勾选具体资料、按关键词/规则持续纳入、精确采集批次。专题新建默认直接选材，支持搜索、关键词、采集批次和分页选择。选择具体资料时不会与整个关键词池做隐式并集。
- 删除任务历史不会删除已经记录的精确成员，已保存批次研究仍可继续使用。每个研究范围沿用最多200条的有界执行；更大批次可在资料库选择子集。运行中的批次新增成员出现在下次预览，当前分析的冻结清单不变。

## 数据文件页

统一为工作台现有配色、留白和字体，取消旧版霓虹效果。按内容、评论、作者、搜索记录等语义分类，不再把随机文件名拆成分类标签；提供数量/体积/格式摘要、文件搜索、分页、紧凑预览和下载。

网页搜索记录优先显示关键词标题，原始路径保留在次要信息中；文件数量与数据行数分别展示，避免把任务元数据对象当作内容集合。内容资料库与导出文件分开显示，可在同一页面切换。

## 验证方式

- 参数链路：界面提交30条、30次滚动、起始批次2；API/CLI契约和核心循环分别验证。
- 模拟搜索：跳过首批、准确截止、已有笔记不请求详情/评论、显式刷新才调用、元数据不含令牌、媒体仍经下载器处理。
- 数据契约：跨关键词成员去重、历史日志边界、任务选择与勾选的精确研究范围、新来源关键词保留、成员事件计数与标题脱敏。
- 浏览器：开始采集请求全部拦截，验证任务→资料→选择→研究、精确批次研究、中文文件分类与预览，并检查桌面/手机布局。仅创建临时样本，不启动真实采集或付费研究。

标准验证为 `scripts/cloud-check.sh`，在本机 Python 3.11、Node.js 22、已安装 Chrome 上执行；实际通过数量及部署结果见本次交付记录，不把本机结果称为 Cloud 验证。
