# 创作引用修复与草稿编辑布局

## 失败原因与修复

本机失败任务的冻结来源中有 56 个上游引用编号。旧实现将整个报告和原证据序列化为正文，再切成当前任务的 35 条证据，模型同时看到两套含义不同的 `E` 编号。上游 `E0036` 至 `E0056` 在当前集合不存在。校验正确拒绝未知引用，但输入没有明确区分两个引用空间。无效模型响应未保存，不能逐项复原当时输出的具体编号。

修复将上游原证据导入独立的 `R` 编号空间，报告中的引用按已知来源映射到这些摘录。保留原证据文本、上游编号和截断标记，目标需求及派生报告上下文不混作原文事实。模型输入只列出当前可用编号；生成用的 JSON Schema 也包含对应枚举。返回报告依然严格校验，未知编号不会被丢弃或强行替换。

新任务保存结构化来源快照，避免长 JSON 被截断后丢失证据。模型侧最多导入 160 条上游摘录、合计 12000 字；加上报告摘要和当前需求后仍受原有 30000 字预算约束。纳入数量与遗漏计入证据覆盖信息。

旧失败任务从检查点恢复到分析节点时，会从原冻结快照重新建立证据，不重新读取可能已变化的父报告。不完整的旧快照会在模型调用前明确报错。本次用户失败任务的快照可完整恢复；只在本机离线检查了证据构建，没有重新调用真实模型，也未改变原任务状态。

## 编辑布局

草稿列表改为顶部下拉选择；新建、预览、导出和保存统一放到工具栏。编辑表单恢复内边距和清晰的字段间距，标题、正文、配图有明确层次。恢复状态使用紧凑提示条，恢复与冲突处理仍保留。

宽屏可并排预览；平板使用完整宽度的编辑画布，默认收起预览。展开预览后自动定位，下方可返回编辑。手机工具栏自动换行。保存、草稿切换、预览、跨页编辑保留均通过临时数据验证。

## 验证边界

按用户在本会话的要求在本机开发。测试使用 Python 3.11、Node.js 22、本机 Chrome、临时数据库和模拟模型。新增回归覆盖 56 条上游引用、长来源、旧检查点恢复、原文保真、引用白名单、非法引用拒绝，以及 825/1440/390 像素布局。不提交用户任务、原文快照、日志或数据库。
