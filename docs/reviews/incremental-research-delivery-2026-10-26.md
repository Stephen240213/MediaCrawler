# 三维增量研究：本轮交付与验收

日期：2026-10-26。承接 [三维内容研究设计](keyword-incremental-analysis-design-2026-10-26.md)。本轮沿用用户先前明确授权的本地开发方式，没有创建 Cloud 任务；测试使用临时数据库、模拟模型和本机 Chrome，不代表真实模型效果、真实采集或 Cloud 环境已验证。

## 使用方式

1. 打开「AI 内容分析」，选择三个并列维度：单条内容、单账号、专题与类目资产。
2. 单条维度保留原有「深度拆解与按需改写」，新增「共享素材研究（不生成改写）」。后者与账号、专题共用中性理解；原有带账号需求的完整改写报告没有被冒充为通用素材缓存。
3. 新建研究范围：单条指定内容 ID；账号选择实际发布者；专题指定采集来源关键词、包含词或人工纳入内容 ID。支持排除、发布时间窗口和归档。时间按 Asia/Shanghai 解释，未知发布时间不会进入指定时间窗口。
4. 「更新本机纳入范围」只读取本机资料。「本次增量范围」显示待理解正文、可复用正文、待处理评论、撤回项及逐条清单。页面每30秒对当前范围重新对账，不自动发起采集或付费调用。
5. 核对范围，设置本批模型调用上限并确认发送后，点击「仅分析新增与变化，并更新综合」。正文、评论和受影响分组分开调用，沿用后台单串行执行器。调用数是边界，金额依供应商账单计算；没有价格表时不伪造人民币报价。
6. 在研究版本中查看覆盖、时间、互动已知值、素材理解、分组观察、缺口和引用原文；在类目资产中搜索、按类目/标签筛选并保存多个标签，可用 `旅居 / 费用` 表达层级。
7. 将确定研究版本关联内容项目。项目显示固定快照和「有新研究版本可用」提示，不自动跟随新报告。
8. 下游深度改写选择该项目后，可明确勾选「使用项目明确引用的研究版本」。任务冻结最多3个研究版本的部分候选资产及原文摘录；默认不加入。引用仍是待核实来源与候选解释，不能作为目标账号偏好、个人经历或其他案例事实直接移植。分析范围说明列出实际采用的研究快照。

## 数据与计算边界

- 本轮支持已经保存的小红书标题、正文和评论。正文最多12000字；没有原始正文的导入记录明确显示仅标题。此次批量研究不重新下载媒体、不执行 ASR、不分析画面；原有单条视频转写流程保留。
- 单条、账号和专题都是独立研究对象。账号身份优先使用原始表中由发布者 ID 生成的匿名 `creator_hash`；兼容历史原始 ID 时只派生平台内标识，不复制原始 ID。`analytics.author_id` 可能来自昵称哈希，因此不将它直接作为可靠账号身份。缺少可靠标识的资料仍可进入单条/专题。
- `source_keyword_memberships` 为追加的多对多关系。归一化保存及数据库触发器保留今后观察到的关键词关联，与采集事务一起提交/回滚。存量只初始化尚存的 scalar keyword，不推测早期丢失的关联。新增表会在显式 analytics 初始化、导入或下次采集初始化时建立；只读预览兼容尚未迁移的数据。
- 素材版本由平台/内容 ID、标题和实际纳入正文计算。中性缓存还包含模型、服务端点、规则/Schema版本。运营画像、创作目标、互动数及采集时间不进入正文语义缓存。
- 评论按稳定 ID 与完整文本版本分别计算贡献；只将当前样本的前500字发送模型。同文不同 ID 的出现次数保留，不把文字去重当作需求计数。每条素材按 comment_id 取最多100条，明确报告保存、抽样、分析数量和涉及素材数；不是全部观众统计，也不是情绪比例。
- 来源修订、评论编辑/删除、人工排除和作者归属修正会更新当前贡献；未变化部分沿用缓存，历史研究保持可追溯。只有互动变化时更新代码统计，不触发正文/评论/综合模型调用。
- 综合使用固定类目与平台内容 ID 的16个固定哈希分组。签名来自当前有效结构化资产和原文证据；不会反复只把旧摘要与新摘要混合。新增来源只影响所属分组；账号综合与专题综合采用不同研究任务。
- 综合有输入大小限制，显示综合纳入资产数。超限分组标为部分完成，未纳入资产仍可在类目中查阅，需要缩小范围/时间后综合。当前没有宣称跨全部分组完成了全局冲突裁决或因果分析。
- 每个研究范围最多200条素材，SQL先按单条、账号、关键词、内容词与时间缩小候选；候选仍超过5000条时要求缩小范围。选择器最多展示匹配的5000条，支持按标题、昵称或内容 ID 继续搜索；不要求删除原始资料库。
- 批次最多40次模型调用，正文和评论成功结果立即缓存；部分失败继续其他条目，超限项待下一轮。队列总上限5个，旧单条任务与研究任务共用，按提交时间串行执行。
- 运行中新增资料属于下一批。超时、断网、服务重启或取消时，进行中调用可能已计费；保留失败/结果未知记录，不自动重试供应商请求。用户建立下一批后才继续未完成部分。
- 研究输入、结果、版本和标签保存在现有 analysis.sqlite3，纳入现有完整工作区备份。批次大输入单独存储，避免每条进度更新反复重写全部正文与评论。历史列表只加载版本头，完整快照按需读取。
- 所有新增写入继承 operator、CSRF和审计边界；恢复草稿仍按访问身份隔离。中性研究不写入目标账号的写作经验库，不覆盖文稿、制作文件或发布记录。

## 本轮没有开启的部分

- 持续自动付费执行与采集触发器。当前是自动发现本机差异、人工提交有界批次。
- 批量视频/画面理解、跨素材 ASR 文件缓存、向量检索和自动生成完整多平台作品。
- 自动把来源声明认定为核实事实，或把「方法候选」升级为已经验证的爆款规律。
- 自动将新研究覆盖到旧项目。研究在当前视图更新，创作通过明确引用的版本取用。

## 验证

新增回归覆盖共享缓存、无变化零调用、互动变化、评论新增/编辑/删除、正文修订、同文评论计数、多关键词去重、真实匿名发布者身份与昵称分离、作者修正撤回、冻结范围、部分失败与预算、归档、重启结果未知、固定项目引用、类目标签并发版本、旧正文恢复的版本顺序、超过5000条资料库的窄范围查询，以及下游研究明确选用。

页面回归使用真实本机 API 与临时库、模拟研究模型，验证三种入口、增量预览、评论独立调用、类目标签与证据下钻、账号复用、项目固定引用，并保存桌面/手机截图到 `/tmp/mediacrawler-research-proof/`。外部平台、付费模型、真实采集与发布均未用于验收。

本机验证命令：

```sh
UV_CACHE_DIR=/tmp/mediacrawler-uv-cache UV_NO_SYNC=1 \
MEDIACRAWLER_TEST_BROWSER='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
bash scripts/cloud-check.sh
```

最终执行结果、部署备份与提交信息以聊天交付记录为准。`api/webui/` 是本机生成文件，不纳入提交；不提交运行数据库、采集内容、模型、凭证或私有配置。

实际检查：本机完整脚本通过280项测试（64项基础回归、212项内容/权限/数据回归、4项浏览器回归），前端生产构建通过；匿名发布者16位标识兼容修正后，15项研究专项再次通过。未安装新依赖。浏览器测试同时验证单条共享理解和项目勾选研究后使用固定版本的下游分析。资产列表每页20项，避免一次渲染整个素材池的评论资产。
